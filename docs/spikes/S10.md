# S10 — custo do modo CLI do executável e do hook curl

Data: 2026-10-22 · Linux x64 (Fedora Atomic, GNOME/Wayland) · electron 44.9.3 · curl 8.18.0

## Montagem
App Electron mínimo: com `mcp` em `argv` conecta no socket Unix, manda `{"ping":1}\n`, espera `{"pong":1}` e faz `app.exit(0)`, antes de `requestSingleInstanceLock`, sem janela, com `app.dock?.hide()`. Sem `mcp`: pega o lock, escuta o socket e responde pong. Nenhum `BrowserWindow` é criado em nenhum dos caminhos.

## Modo CLI (100 execuções de `electron . mcp --no-sandbox`, instância aberta)
| cenário | p50 | p95 | min / max |
|---|---|---|---|
| com display (Wayland) | 177 ms | 181 ms | 173 / 184 |
| `env -u DISPLAY -u WAYLAND_DISPLAY` | 178 ms | 181 ms | 174 / 182 |

- Sem display não abortou; `--ozone-platform=headless` não foi preciso. Exit code 0 nas 200 execuções.
- PID da instância principal inalterado (497576) e processo único após as 200 chamadas (nenhum segundo servidor/lock). Nenhuma janela é criada pelo código; checagem visual por ferramenta de janelas não disponível (sem wmctrl/xdotool, `Shell.Eval` do GNOME bloqueado).
- Limite era p95 ≤ 300 ms: **passa com folga** (~181 ms).

## Hook curl (`curl -s -m 1 -X POST ... || true`, via `bash -c`)
Reproduzível: `spike-s10/hook-bench.sh` (scratch; sobe `srv.js` com 204 em :18401, servidor mudo em :18402, porta :18403 fechada). Comando medido:
```
bash -c 'curl -s -m 1 -X POST -H content-type:application/json -d {"e":"Stop"} http://127.0.0.1:<porta>/hook || true'
```
| cenário | n | p50 | p95 | exit != 0 |
|---|---|---|---|---|
| servidor loopback responde 204 | 100 | 3 ms | 4 ms | 0 |
| porta fechada | 100 | 3 ms | 3 ms | 0 |
| aceita e não responde | 20 | 1005 ms | 1006 ms | 0 |

Limites: p95 <= 100 ms (204 e porta fechada passam); servidor mudo <= 1,2 s com exit 0 (passa, o teto é o `-m 1`).

## Ressalvas do que foi medido
- Só execuções **quentes** (instância já aberta, binário em cache de página). Cold start do Electron não foi medido.
- Só **Linux x64**. Windows/macOS sem números.
- NÃO foi observado com ferramenta: (a) que o `electron . mcp` não rouba foco nem traz a instância aberta para frente; (b) que não aparece ícone no dock (no Linux `app.dock` é undefined, o `?.hide()` é no-op). A ausência de janela vem só do código (nenhum `BrowserWindow`) e do PID/processo único.

## Decisão (PROVISÓRIA, só Linux)
- CLI no próprio executável (`turnflow mcp`): p95 ~181 ms no Linux. Provisório: Windows é o caso mais provável de ficar lento e não tem número; `turnflow-bridge` continua como plano B se p95 > 300 ms lá.
- Hook = curl: p95 ~4 ms no Linux; falha silenciosa com `|| true` e teto de 1 s via `-m 1`. Provisório até medir mac/Windows (no Windows o curl.exe e o `||` dependem do shell do hook).

## Pendente de validação

- mac/Windows/GNOME: foco/instância em primeiro plano, ícone no dock, janelas realmente ausentes (com ferramenta).
