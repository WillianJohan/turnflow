# S1 — SQLCipher + node-pty no Electron 44

Data: 2026-10-22 · Máquina: Fedora Atomic, Linux x64 · Node 24.10 (host) / 24.22 (Electron)

## Versões
- electron 44.9.3 (`^44.7.2`, mesma faixa do dkdesk), ABI 149
- better-sqlite3-multiple-ciphers 13.0.3 (SQLite 3.53.4 embutido)
- node-pty 1.1.0
- electron-builder 26.15.3

## Comandos
```
npm i -D electron@^44.7.2 electron-builder
npm i better-sqlite3-multiple-ciphers node-pty
npx electron-builder install-app-deps
npx electron . --no-sandbox        # main.js: sem janela
```

## Instalação / build
- `npm i` das libs: ~5 s. `install-app-deps`: ~3 s. Nada compilou do zero.
- better-sqlite3-multiple-ciphers publica `prebuilds/*.node` (linux x64/arm64/musl, darwin x64/arm64, win32 x64/arm64) dentro do pacote.
- node-pty 1.1.0 traz prebuilds só de darwin e win32; no Linux o `install-app-deps` recompilou o `pty.node` (leve, ~3 s, gcc/g++/make presentes).

## Saída (3 execuções idênticas)
```
electron 44.9.3 node 24.22.0 abi 149
version 3.53.4 >=3.45
fts=1 hit
pty-ok
plain=unreadable | Parse error ...: file is not a database (26)
```
- `pragma cipher='sqlcipher'` + `pragma key='x'`: ok.
- FTS5 `tokenize='trigram remove_diacritics 1'`: "acao" encontra a linha "ação" (1 hit).
- PTY `bash -c 'echo pty-ok'` dentro do Electron: ok.
- `sqlite3` CLI (3.54.0) sem chave: "file is not a database" — arquivo cifrado.

## Decisão
**lib = better-sqlite3-multiple-ciphers@13.0.3.** Fallback `@journeyapps/sqlcipher` não foi necessário.

## Pendente
- macOS e Windows: matriz do `.github/workflows/spike-s1.yml` rodou em 22/10/2026 (run 39708015247), verde nos 3 SOs: Electron 44.9.3, sqlite 3.53.4, fts=1, pty-ok, plain=unreadable. **A decisão vale para Linux, macOS e Windows.**
- Achado no Windows: com `app.exit()` logo depois do pty terminar, o processo saía com 1 mesmo com as checagens verdes (run 39707712335); esperando o `onExit` do conpty, sai com 0. O E5 (terminal) precisa matar o pty e esperar o exit antes de encerrar o app no Windows.
- Em Windows/mac o node-pty usa prebuild; atenção ao shell (`cmd.exe`) no workflow.
- xvfb-run não existe nesta máquina; o teste local rodou direto no Wayland (o spike não abre janela). O xvfb só é usado no job Linux do CI.

## Revisão 1 do workflow
O `main.js` embutido no workflow foi extraído do YAML e rodado localmente no Linux (2x, rc 0): sqlite 3.53.4, fts=1, pty-ok, "SQLITE_NOTADB file is not a database" -> plain=unreadable. O job falha se `sqlite_version() < 3.45`, se o erro sem chave não for "not a database", ou em rejeição não tratada. O token do PTY é montado em runtime (`pty-42`) para a linha de comando ecoada não casar (no Windows via `cmd /v:on`, executado no CI).
